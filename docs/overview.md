# 俺たちの雀歴 — アプリ概要

## プロジェクト名称

| 用途 | 名称 |
|------|------|
| 製品名（日本語） | **俺たちの雀歴** |
| 開発用英語名 | **Our Mahjong History** |

UI 上の表記（アプリ名、ページタイトル、OG タイトル等）は **俺たちの雀歴** を用いる。リポジトリ名・パッケージ名等の識別子には **Our Mahjong History**（`our-mahjong-history`）を用いる。ドメイン用語の日本語と、表名・カラム・パスの英語識別子は別である。日本語の正は本ファイル。表名は [er.md](er.md)。日本語を変えても英語識別子は変えない。

## ドキュメントの役割

本ファイルは **ドメインの正**（用語、関係、保存 vs 計算、誰が何をできるか、MVP 範囲）。属性・制約・ER 図・テーブルごとの RLS 判定は [er.md](er.md)。画面遷移・部品・トークンは [ui-spec.md](ui-spec.md)。進捗は [status.md](status.md)。フェーズ定義は [development.md](development.md)。

## 目的

麻雀仲間の **麻雀グループ** で、麻雀大会および各試合（半荘）の結果を記録・共有する Web アプリケーション。**対局記録専用**であり、賭け麻雀や金銭のやり取りは扱わない。

## 扱わないもの（方針）

麻雀には賭け事のイメージがあるが、本アプリはそれを想定しない。賭博は法律に違反する犯罪である。

- **賭け麻雀・賭け事は扱わない**
- **金額・通貨は扱わない**（円換算、精算、支払い、賭け金）
- 記録・表示・保存するのは **点数**（持ち点）、**基本ポイント**、**ポイント**（ウマ・レート等を加味した得点）のみ
- **レート** はポイント計算の係数であり、円単価・賭け金単価ではない
- UI・ドキュメント・コード・説明に「金額」という言葉を使わない

## 想定ユーザー

- 定期的に麻雀をする仲間同士のグループ
- 大会の結果を後から振り返りたいプレイヤー
- スマートフォンから手軽に記録・閲覧したいユーザー

## アプリ種別

- 複数ユーザーがログインし、所属する麻雀グループのデータを共有する
- 麻雀グループは卓や麻雀大会とは独立して存在（麻雀仲間の単位）

## ドメイン構造

```
麻雀グループ（麻雀仲間の単位）
  ├── メンバーシップ（ユーザーとの N:M。役割は持たない）
  ├── 招待コード（最大 1。有効期限あり）
  ├── 既定ルール（複数。テンプレート。大会ルールとは別エンティティ）
  └── 麻雀大会（複数）
        ├── 大会参加者（メンバーまたはゲスト）
        │     └── 大会修正ポイント（1〜5。タイトルは大会、値は参加者）
        ├── 大会ルール（複数。作成時に既定を値コピー。コピー元 FK なし）
        └── 試合 / 半荘（複数）
              ├── 使用ルール（大会ルールから 1 つ）
              └── 試合結果（プレイヤーごと。3 または 4）
```

- **麻雀グループ**: 最上位の集まり。メンバー管理・ルール設定の単位。名称とコメント（説明）を持つ。識別子は `communities` / `community_id`
- **麻雀大会**: ある日開催された大会。複数の試合を含む。**複数ルールを併用できる**（四麻卓と三麻卓の混在など）
- **試合（半荘）**: 半荘 1 回分の記録。**局単位の記録は不要**。その大会のルールから 1 つを選んで使う

### 関係と多重度（Phase 1-1 / 1-2 / 1-4 / 1-5）

| 関係 | 多重度 | 備考 |
|------|--------|------|
| ユーザー — 麻雀グループ | N:M | 所属。1 ユーザーが複数の麻雀グループに入れる。役割は持たない。実体は `profiles` |
| ユーザー — 操作ログ | 1:N | 監査用。アプリ UI には出さない |
| 麻雀グループ — 招待コード | 1:0..1 | 有効期限付き。再発行で差し替え |
| 麻雀グループ — 麻雀大会 | 1:N | 大会は必ず 1 つの麻雀グループに属する |
| 麻雀グループ — 既定ルール | 1:N | テンプレート。三麻用・四麻用など複数可 |
| 麻雀大会 — 大会参加者 | 1:N | 大会作成時は 0 人でもよい |
| 麻雀大会 — ルール | 1:N | 作成時に麻雀グループの既定をコピー。大会側で追加も可 |
| 麻雀大会 — 試合 | 1:N | 試合は必ず 1 大会に属する。大会に試合 0 件も可 |
| 試合 — ルール | N:1 | その大会のルールから 1 つを選ぶ |
| 試合 — 試合結果 | 1:3 または 1:4 | その試合の使用ルールの人数（三麻 / 四麻）に従う |
| 大会参加者 — 試合結果 | 1:N | 同一大会で複数試合に出られる |
| 試合結果 — 大会参加者 | N:1 | プレイヤーは大会参加者を指す。ユーザーを直接指さない |
| 大会参加者 — 大会修正ポイント | 1:0..1 | タイトルは大会が持つ。値は参加者あたり最大 1 行 |
| ユーザー — 大会参加者 | 1:N（任意） | メンバーのときだけ。ゲストは表示名のみ |

試合のプレイヤーは、その大会の参加者の **部分集合** である。

麻雀グループの既定ルールと大会ルールは **別エンティティ**。権限・招待・操作ログは [権限モデル](#権限モデルphase-1-5)。

### プレイヤーの指し方（Phase 1-1）

試合に出せるのは次の 2 種。どちらも **大会参加者** として大会に載せる。

| 種別 | 内容 |
|------|------|
| **メンバー** | その麻雀グループに所属するログインユーザー |
| **ゲスト** | アカウントなしの **表示名**。ログインできない。麻雀グループ横断の名簿や名寄せはしない |

- ゲストは大会ごとの名前である。別大会の同名ゲストは同一人物として扱わない
- 麻雀グループに所属している人はメンバーとして参加させる。ゲストと二重登録しない（アプリ制約。DB の XOR だけでは検知しない）
- 離脱・除名・退会しても、過去の大会参加者の `user_id` は残す。ゲストへ載せ替えない
- 大会の編集で参加者を外すのは別操作。試合に出ていても外せる。その人の試合結果と修正ポイントは消える。試合の行は残る。麻雀グループの離脱（対局は残す）とは違う
- 離脱・除名のあとの表示名は、**いまの** `profiles.display_name`（現行名でよい）
- 退会した人の表示名は、プロフィール側が「退会済みユーザ」になる（当時の実名は残さない）
- 再登録は新しいプロフィール（別人）。墓石とはつなげない
- 表示名、コメント（自己紹介）、Google / LINE のアイコン表示は MVP。登録時の表示名は Auth の `user_metadata.display_name`（無ければ `full_name` / `name`、さらに無ければメールの `@` より前）。アイコンは Google / LINE ログイン時に Auth の `avatar_url` / `picture` を `profiles` へコピーする。メール登録は空で頭文字。アップロードはしない
- 「プレイヤー個人の詳細管理」（通算成績、名寄せ）は MVP 外のまま
- データを閲覧・編集できるのは麻雀グループのメンバーのみ。ゲストは記録上の名前であり、利用者ではない

### 保存と計算（Phase 1-1）

| 値 | 入力 / 計算 | 保存 |
|----|-------------|------|
| 点数（持ち点） | 手入力 | 保存する |
| 家 | 手入力（東南西北） | 保存する |
| 基本ポイント | 点数にオカのみを反映して保存時に計算。オカ同着が手動（1 位同着）のときは出場者全員を手入力 | 保存する（`base_points`）。オカ単体は持たない |
| ウマ・トビ・焼き鳥 | 自動計算できるものは保存時に計算、できないものは手入力 | 試合結果の内訳として保存する |
| その他ポイント（1〜5） | ルールで名称を付ける。値は試合で手入力 | 名称はルール、ポイントは試合結果 |
| 試合個別の手動ポイント（1〜3） | 試合でタイトルを付ける。値は試合結果で手入力 | タイトルは試合、ポイントは試合結果 |
| 試合のポイント | 基本ポイントにウマ・トビ等とレートを加味した合計 | 合計を保存する |
| 試合の順位 | **点数（素点）**の高い順で保存時に計算。同点は同位で次を飛ばす（1, 2, 2, 4） | 計算結果を保存する |
| 大会修正ポイント | 手入力（チップや会場提供の優遇などを **ポイントの加減** として） | タイトルは大会（1〜5）。値は参加者の修正行（同番号） |
| 試合ポイント合計 | その参加者の試合結果ポイントの合計 | 保存しない（都度集計） |
| 最終ポイント | 試合ポイント合計 + 大会修正ポイント | 保存しない（都度集計） |
| 最終順位 | 最終ポイント順。同ポイントは同位で次を飛ばす（1, 2, 2, 4） | 保存しない（都度集計） |

1 件でも試合が紐づいた大会ルールは **修正不可** である。内容を変えたい場合はルールを新規登録し、以降の試合でそれを選ぶ。未使用の大会ルールは修正できる。麻雀グループの既定はテンプレートなので、既存大会のルールには影響しない。

保存済みのポイント（基本ポイント・内訳・合計）・順位は、ルールを後から増やしても **変わらない**。点数を直して再保存したときは、その試合が参照している（不変の）ルールで基本ポイントと自動計算分を再計算し、順位を点数から付け直す。

試合の順位は **点数（素点）** から付ける。同点は同位で次を飛ばす（1, 2, 2, 4）。オカの上家取りで基本ポイントが分かれても、素点が同じなら順位は同じ。ウマの上家取りも順位を分けない。上家取りは **家**（東→南→西→北）で先の席が取る。折半の端数は上家が 0.1 ポイント多くなる（式の正は [calc-cases.md](calc-cases.md)）。

### 大会サマリー（Phase 1-3）

正は **試合結果** と **大会修正ポイント** である。最終ポイント・最終順位は大会に保存しない。

- **試合ポイント合計** = その大会参加者の、各試合結果ポイントの合計（三麻・四麻混在やレート差も、保存済みの試合ポイントをそのまま足す）
- **大会修正ポイント** = その大会参加者の修正ポイント 1〜5 の合計。タイトルは大会が持つ（例: チップ、会場優遇）。試合のポイントとは別に持つ
- **最終ポイント** = 試合ポイント合計 + 大会修正ポイント
- **最終順位** = 最終ポイントの高い順。同ポイントは同位、次の順位は飛ばす（例: 1, 2, 2, 4）
- 順位・最終ポイントの対象は **1 試合以上出場した参加者**。未出場は参加者リストに残すが、順位対象外
- 大会修正ポイントは大会参加者に付ける（未出場者にも付けられる）。未出場者の修正は最終順位には載せない
- 修正のゼロサム制約は持たない。タイトルが空の枠は未使用（値は 0）
- 画面上の見せ方・入力手順は Phase 2

## 用語定義

| 用語 | 意味 |
|------|------|
| **点数** | 半荘終了時の各プレイヤーの **持ち点**（素点） |
| **基本ポイント** | 点数にオカのみを反映したポイント（レート・ウマ・トビ等は含まない）。試合結果に保存する |
| **ポイント** | 試合結果に保存する合計。基本ポイントにウマ・トビ・焼き鳥・その他・試合個別手動とレートを加味した得点 |
| **試合** | 半荘 1 回分。本ドキュメントでは「試合」=「半荘」として扱う |
| **麻雀大会** | 日付・名称等を持つイベント。複数試合の容器 |
| **大会参加者** | その大会に出る人。麻雀グループのメンバーまたはゲスト |
| **ゲスト** | アカウントを持たない大会参加者。表示名のみ |
| **ユーザー** | ログインできる人。アプリ側の実体は `profiles`（利用中）。Auth は `auth.users` |
| **墓石** | 退会した利用者の `profiles` 行。ID は残し、表示名は「退会済みユーザ」。ログインできない |
| **家** | 東南西北の席。四麻は東・南・西・北、三麻は東・南・西。上家取りの判定に使う |
| **試合結果** | 1 試合における 1 参加者の家、点数、基本ポイント、ポイント内訳（ウマ・トビ・焼き鳥・その他・試合個別手動）、合計ポイント、順位 |
| **ルール** | 点数からポイントを出すための設定。麻雀グループの既定（テンプレート）と、大会にコピーした実体がある |
| **レート** | ルールの第一級項目。ポイント計算の係数。円単価・賭け金単価ではなく、金額への換算には使わない |
| **大会修正ポイント** | 試合とは別に、大会参加者へ付けるポイントの加減。タイトル 1〜5 は大会、値 1〜5 は参加者 |
| **最終ポイント** | 試合ポイント合計 + 大会修正ポイント。保存せず都度集計 |
| **最終順位** | 最終ポイントに基づく大会内順位。保存せず都度集計 |
| **麻雀グループ** | 麻雀仲間の単位。メンバー・既定ルール・大会の入れ物。識別子は `communities` / `community_id`（パスは `/communities`） |
| **招待コード** | 麻雀グループ参加用のコード。有効期限あり。麻雀グループあたり最大 1 |
| **操作ログ** | 麻雀グループ・大会・試合の追加・修正・削除の監査記録。アプリ UI には出さない。開発者が確認する |

## 点数計算ルール

半荘単位の入力のため、アガリ役等は扱わない。

### 置き場所（Phase 1-2）

- **麻雀グループ** は既定ルール（テンプレート）を複数持てる
- **大会** 作成時に麻雀グループの既定をコピーする。既定が 0 件なら大会ルールも 0 件で始まり、あとから追加できる
- 1 大会で **複数ルールを併用** できる（例: 四麻卓と三麻卓の混在）
- **試合** は、その大会のルールから 1 つを選ぶ（必須）。ルールが 0 件の大会では試合を作れない
- 1 件でも試合が紐づいた大会ルールは **修正不可**。変えたい場合はルールを新規登録する（修正の代わり）

### 第一級項目（Phase 1-2）

計算式の細部の正は [calc-cases.md](calc-cases.md)。意図（同着の意味など）は本節。実装は `web/src/lib/domain/`。

| 項目 | 内容 |
|------|------|
| 表示名 | 同一麻雀グループ（または同一大会）内で一意。「四麻標準」「三麻」など |
| 人数 | 三麻 / 四麻。試合結果の人数もこれに従う |
| 持ち点・返し点 | ○○点持ち ××点返し |
| オカの同着時 | **上家取り** / **折半** / **手動**。同着は **点数 1 位** の同着。上家取りは家の順（東→南→西→北）。折半の端数は上家が 0.1 多く取る。手動のときは 1 位同着なら **出場者全員** が基本ポイントを手入力する（オカ単体は持たない）。1 位が 1 人なら自動 |
| ウマの有無 | なしのとき、以下のウマ項目は使わない |
| ウマの同着時 | **上家取り** / **折半** / **手動**。同着は **点数**（試合順位）の同着。上家取りは家の順（東→南→西→北）。折半は順位スロットのウマ合計を同着者で分配し、端数は上家が 0.1 多く取る |
| ウマのポイント1 | 最上位 ⇔ 最下位 |
| ウマのポイント2 | 2位 ⇔ 3位（**四麻のみ**） |
| トビの有無 | |
| 焼き鳥の有無 | ありのとき、実際のポイントは試合で手入力 |
| その他ポイント 1〜5 | 名称のみ（例: 役満ご祝儀）。未使用は空。値は試合結果で手入力 |
| レート | 第一級。小数、0 以上 |
| メモ | 自由記述。計算には使わない |

ポイントは、点数から自動計算できるものは自動計算し、点数から出せないもの（焼き鳥、オカ同着時の基本ポイント手動、ウマ同着時の手動、その他ポイント、試合個別の手動ポイントなど）は手入力する。基本ポイント・内訳・合計は試合結果に保存する。オカは基本ポイントに含めて保存し、列としては持たない。

試合には、ルールとは別に **試合個別の手動ポイント 1〜3** を持てる（タイトルは試合、値は試合結果）。

麻雀グループの既定と大会ルールは **別エンティティ**（共通列 + 親 FK）。コピーは値の複製であり、コピー元 FK は持たない。

## MVP スコープ

### 含む

- 認証（ログイン / サインアップ）
- ログインユーザーの表示名とコメント（自己紹介）
- Google / LINE のアイコン表示（メール登録は頭文字。アップロードはしない）
- 麻雀グループの作成・所属（招待コード）、離脱・除名、アプリ退会（墓石）
- 麻雀グループの既定ルールと大会ルール
- 麻雀大会の CRUD（登録・一覧・編集・削除）
- 大会参加者（メンバーおよびゲスト）
- 試合（半荘）の CRUD
- ルール設定に基づくポイント計算
- 大会サマリー（参加者・最終順位・最終ポイント。試合合計 + 大会修正）

### 含まない（将来拡張）

- 写真アップロード（対局写真、およびプロフィールアイコンの独自アップロード）
- 成績・統計（勝率、順位分布等）
- プレイヤー個人の詳細管理（ゲストの名寄せ、通算成績。ログインユーザーの表示名・コメント・Google/LINE アイコン、ゲスト表示名は MVP に含む）
- 結果のエクスポート・共有
- PC 向けレイアウトの最適化
- 公開ルーム、局単位の記録、アガリ役・和了情報
- 操作ログのアプリ UI（開発者確認のみ）

## 権限モデル（Phase 1-5）

実装は Phase 3 の RLS / 関数。ここでは誰が何をできるかだけ決める。公開ルームは MVP 外。

### 役割

メンバーは **全員同等**。作成者・管理者の区別は持たない。`community_memberships` に役割カラムは置かない。

### アクセスの単位

権限の正は **麻雀グループへの所属** である。大会に出ていなくても、所属していればその麻雀グループ配下を読める・書ける。テーブルごとの SELECT / INSERT / UPDATE / DELETE と判定経路は [er.md の RLS 方針](er.md#rls-方針)。

| 対象 | 読める | 書ける（追加・修正・削除） |
|------|--------|----------------------------|
| 麻雀グループ本体 | 所属メンバー | 修正・空のときの削除は所属メンバー。作成はログイン済みなら誰でも（関数） |
| 既定ルール・招待コード | 所属メンバー | 所属メンバー |
| メンバーシップ | 所属メンバー（一覧） | 離脱・除名は所属メンバー。参加と作成時の加入は関数のみ。UPDATE なし |
| 大会・大会ルール・参加者・修正ポイント | 所属メンバー | 所属メンバー |
| 試合・試合結果 | 所属メンバー | 所属メンバー |
| 操作ログ | 不可（UI にも出さない） | アプリからは書けない。対象表の trigger が記録。UPDATE/DELETE 不可 |
| 他の麻雀グループのデータ | 不可 | 不可 |
| プロフィール（`display_name`） | 本人、**同じ麻雀グループの所属者**、および **自分が所属する麻雀グループの大会参加者として載っている人**（離脱・退会後の墓石を含む） | 本人のみ（表示名・コメント）。退会は `withdraw_account`。直接の墓石化 UPDATE はしない |

ゲストは記録上の名前であり、ログインもデータ操作もしない。

### 麻雀グループの作成・参加・離脱・削除

| 操作 | 誰が | 条件 |
|------|------|------|
| 麻雀グループ作成 | ログイン済みなら誰でも | 作成と同時に自分をメンバーにする（`create_community`） |
| 参加 | ログイン済みなら誰でも | **有効期限内の招待コード** が必要（`join_community`）。既に所属していれば何もしない |
| 招待コードの発行・再発行 | 所属メンバー | 麻雀グループあたり最大 1。再発行で旧コードは無効。期限の長さはアプリが `expires_at` に書く（既定日数は Phase 2〜4） |
| メンバーの除名 | 所属メンバー | 自分以外も外せる。`community_memberships` の直接 DELETE。プロフィールは消さない |
| 離脱（自分） | 本人 | `leave_community`。他にメンバーがいるときはいつでも可 |
| 麻雀グループの明示削除 | 所属メンバー | **空のときだけ**（大会 0 件かつ既定ルール 0 件）。残っているメンバーシップ・招待コードは一緒に消す。操作ログは残す |
| 最後の 1 人の離脱 | その人 | 麻雀グループごと消す。大会や既定ルールが残っていても **まとめて消す**（孤児を残さない） |
| アプリ退会 | 本人 | `withdraw_account` で墓石化する。**すべての麻雀グループから離脱**（最後の 1 人なら上と同じ）。`auth.users` を消すのは Server Action。`profiles` 行は残す |

未ログインでコードだけ知っていても参加できない。ログイン（または新規登録）後にコードを使う。画面上の手順は Phase 2。

### 麻雀グループ離脱・除名

`community_memberships` の該当行だけ消す。`profiles` は触らない（匿名化しない）。

| 項目 | 方針 |
|------|------|
| 過去の対局 | 大会参加者の `user_id` は残す。試合結果は参加者経由でそのまま参照できる。ゲストへ載せ替えない |
| 表示名 | **いまの** `profiles.display_name` で見せてよい（当時の名前のスナップショットは持たない）。あとから本人が改名すれば過去対局の表記も変わる |
| 残メンバー | その人が大会参加者として載っているプロフィールを読める（所属は切れている） |
| 抜けた本人 | その麻雀グループ配下は読めない・書けない。他の麻雀グループと自分のプロフィールは従来どおり |
| 再参加 | 招待コードで同じ `profiles` のまま戻れる。過去の大会参加者行はそのままつながる |
| 最後の 1 人 | 麻雀グループごと消す。対局記録も消えるので、上の「残して参照」は起きない |

除名もデータ上は同じ（対象のメンバーシップを消す。プロフィールは残し、名前は現行の表示名）。

未出場の大会参加者も `user_id` を持つ。名前の参照は **大会参加者 → プロフィール** が正。試合結果はその先にある。

### 退会（墓石）

`profiles` 行は **消さない**。子の FK を保つ。

| 項目 | 方針 |
|------|------|
| 表示名 | 「退会済みユーザ」（過去対局もこの名前。当時の実名は残さない） |
| コメント | 空にする |
| アイコン | 空にする |
| Auth | `auth_user_id` を NULL にし、`auth.users` を消す。同じメールでの再登録は新しい `profiles`（別人） |
| 所属 | すべての麻雀グループから離脱する。最後の 1 人なら麻雀グループごと消す |
| 大会参加者 | `user_id` は墓石を指したまま。ゲストへ載せ替えない |
| 操作ログ・招待の作成者 | 墓石の ID を指したまま |

実装は Phase 3。経路は次の 2 段で、**独自 REST は作らない**。

1. **PostgreSQL の関数** `withdraw_account`（SECURITY DEFINER）: 匿名化（表示名を「退会済みユーザ」、コメントと `avatar_url` を空）、`withdrawn_at`、`auth_user_id` を NULL、すべての麻雀グループから離脱（最後の 1 人なら麻雀グループ削除）。`withdrawn_at` / `auth_user_id` / 表示名「退会済みユーザ」への直接 UPDATE は不可
2. **Server Action**: ログイン中の本人が呼び、上の関数を Supabase RPC で実行したあと、**Auth Admin（service role）** で `auth.users` を消す。Auth 削除は Postgres 関数だけでは行わない

クライアントから複数テーブルを直列に更新しない。

### 招待コード

- 方式は **招待コード**（トークン付き URL やメール招待は持たない）
- 麻雀グループ横断で UNIQUE。参加時に麻雀グループ ID は不要
- 期限切れまで **何度でも使える**（人数上限なし）
- 期限当日は参加できる（`expires_at` ちょうどを含む）。**その日を過ぎた**コードでは参加できない。判定は `Asia/Tokyo` の日付。再発行する
- 形式は **10 文字・Crockford Base32**（字母 `0123456789ABCDEFGHJKMNPQRSTVWXYZ`。I / L / O / U なし）。保存は大文字。参加時は大小無視し、`I`/`L` → `1`、`O` → `0` に正規化して照合する
- 表の SELECT / 発行・再発行は **所属メンバーのみ**。未所属者はコード一覧を読めない

### 麻雀グループ参加（招待コード）

コードを知っているだけでは、`community_memberships` への直接 INSERT 権限は持たない。未所属者は「その麻雀グループのメンバー」ではないため、所属ベースの RLS では書けない。

コード付きの素の INSERT ポリシー（`community_id` が分かれば参加可、など）も採らない。麻雀グループ ID の推測でコードなし参加ができてしまう。

参加は退会と同じく **関数 + Server Action**（独自 REST は作らない）。

1. **PostgreSQL の関数** `join_community`（SECURITY DEFINER）: 引数は招待コード。認証済みであること、コードが存在し期限内であること、`user_id` は呼び出し人（`auth.uid()` に対応する利用中プロフィール）であることを関数内で確認し、`community_memberships` に INSERT する。既に所属していれば何もしない。入力は大文字化し、Crockford の別名（`I`/`L` → `1`、`O` → `0`）を正規化してから照合する
2. **Server Action**: ログイン中の本人が呼び、上の関数を Supabase RPC で実行する

参加後は通常の所属メンバー権限になる。

麻雀グループ作成時の「自分を最初のメンバーにする」も所属チェックでは循環するので、`create_community` でまとめる。`community_memberships` への INSERT は、認証ロールの直接操作としては許可しない（関数経由のみ）。離脱は `leave_community`。除名はメンバーシップの直接 DELETE。

### 操作ログ

麻雀グループ・大会・試合の追加・修正・削除を追う監査テーブル。**アプリの UI には出さない。** 万が一のときに開発者が確認する。値の差分（変更前/後）は持たない。`community_id` は持たない。

| ログに残す操作 | 記録するキー（`entity_id`） |
|----------------|------------------------------|
| 麻雀グループ本体、メンバーシップ、招待コード、既定ルール | 麻雀グループ ID |
| 大会本体、大会ルール、大会参加者、大会修正ポイント | 大会 ID |
| 試合本体、試合結果 | 試合 ID |

- 誰が（`actor_user_id`）・いつ・どの種別・どの ID に対して・追加/修正/削除か
- `entity_type` は任意の文字列（CHECK なし）。trigger は親キーへ寄せるとき `community` / `tournament` / `match` を書く
- **書き手は trigger**（`private.trg_append_activity_log`）。Server Action から直 INSERT しない
- 操作者は `auth.uid()` に対応する利用中プロフィール。seed など取れないときは足さない
- 子の CASCADE 削除では足さない（起点の 1 操作だけ）
- プロフィールの変更は残さない
- RLS: アプリロールは **すべて不可**（SELECT / INSERT / UPDATE / DELETE）。開発者の確認は service role 等
- 対象の麻雀グループ・大会・試合を消してもログは残す

### RLS の伝播（方針）

子テーブルは親の麻雀グループの所属で判定する。試合結果は試合 → 大会 → 麻雀グループ、のように辿る。

- 麻雀グループ一覧: 自分が所属するものだけ
- 行の作成・更新・削除: その行が属する麻雀グループのメンバーであること
- 招待コード表はメンバーだけが読める。未所属者は SELECT できない
- `community_memberships` の INSERT は所属ベースでは循環する。`join_community` / `create_community` のみ（直接 INSERT は許可しない）
- 麻雀グループ作成と最初のメンバーシップは、`create_community` でまとめて行う
- 操作ログはアプリロールでは読めない・書けない。記録は trigger。SELECT は service role 等
- 退会は `withdraw_account` + Server Action。プロフィール RLS の UPDATE だけで墓石にはしない
